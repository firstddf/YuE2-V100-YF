# 歌曲生产线

这是**指导性工作流 + 检查清单**,不是自动脚本。加载后第一步是确认目标,不要直接开始生成。

地基 = `audio.cpp` 引擎(已编入 `yue2,muscriptor`)+ 自己的服务与界面 + 15 个脚本。
图形界面和这个 skill 是**同一套引擎的两个入口**,不是两套系统。

## 何时用

- 用户想"参考某首歌生成一首类似的"。
- 用户想从零构思一首歌(灵感/主题/风格 → 成品)。
- 用户要改已有结果:换风格、调氛围、改时长、改歌词重新生成。

**不适用于**:想"改词翻唱原曲""用指定音色唱"——那是音色替换,属于 Seed-VC / ACE-Step 那条线,本项目**未编入**,需要重编译。

## 第一条铁律:你听不到音频

**本 harness 的输入模态只有 text 和 image**(provider schema 只接受 `"text" | "image"`,`audio` 块是 unknown block type,也没有 `read_audio` 工具)。

所以:

- **不得声称自己"听过"任何音频**,不得凭文件名或元数据想象听感。
- **氛围判断(朦胧不朦胧、够不够虚、像不像人声)只能由用户提供**:要么用户用自然语言描述,要么用户听完整理反馈。
- 凡是"这条听起来够虚""这条更像吟唱"这类结论,**必须标注为待用户确认**,不能当作事实往下走。

## 第二条:能力边界(全部实测过,不得越过)

| 事项 | 事实 | 后果 |
|---|---|---|
| **气声 / 喘息** | 只能做到"哼唱",**没达标** | 不要承诺气声效果;需要真正的喘息要走语音模型混音 |
| **段落留空** | **不会**让人声退场(实测 0:00–41 一直在唱) | 要人声退场必须用 `[Instrumental]` |
| **风格标签** | 影响是**概率性的**,同一提示词两次结果不同 | 不要承诺"一定出某种效果";要出 N 版让用户挑 |
| **ABC 乐谱** | 是模型的"**计划**",与产出音频关系是松的 | 不得用乐谱判断"有没有唱""唱得对不对" |
| **若隐若现 / 若即若离** | 只能做**整轨**;人声单独进退需分轨(未编译) | 不要承诺"只有人声忽远忽近" |
| **ASR** | 对无词吟唱**不可靠**(会把纯元音塞成幻觉短语) | 不得拿 ASR 结果当"有没有人声"的证据 |
| **括号指示 `(音乐:…)`** | 实测**不会被唱**(ASR 三字组命中 0/298),但引擎**不剥括号**、纯靠模型习惯 | 可以当注释用,但**不能说"绝对不会唱出来"**;要确定性就自己删掉 |
| **时长** | 没有时长参数;由歌词长度决定 | 用"最短/最长秒数"换算 `semantic_min/max_tokens` |

只要用户的要求落在这张表的"做不到"一侧,**先说做不到 + 给替代方案**,再决定做不做。

## 第一步:明确输入(必做,缺就问)

- **目标**:"参考某首歌做一首类似的" → 要参考音频路径;**"从零构思"** → 要灵感/主题。
- **相似到什么程度**:风格像 / 节奏像 / 只是气氛像?(决定要不要跑 MuScriptor;见 `references/commands.md`)
- **语言与唱法**:Mandarin / Cantonese / Japanese / English…;有词演唱,还是无词吟唱,还是纯器乐?
- **时长**:目标多少秒(换算见下)。
- **歌词**:用户给词,还是让你写?
- **氛围**:朦胧 / 迷离 / 轻抚 / 若隐若现…(这是**用户侧信息**,你听不到,必须问)
- **交付形态**:要几版?要不要带氛围后期?

若用户只说"做首歌",先补齐上面 5 项再动手。

## 工作流

1. **确认目标**(上一节,必做)。
2. **分析参考**(仅当有参考音频)—— 两级,按需选:
   - `analyze-track.py`(librosa,**零成本秒级**):BPM / 律动 / 调性 / 频谱 / 动态 / 空间 + 标签建议
   - `muscriptor-summary.py`(引擎转谱):**乐器标注 + 真实鼓型**,音符级
   - 把测出来的特征**翻译成标签**,不要直接照抄数字(映射规则见 `references/style-tags.md`)
   - **图形界面里也有同一件事**:「🔍 参考曲分析」页签(第 5 个),或 `POST /api/analyze`。
     用户在手边时优先让他去点,他还能当场听、当场改标签 —— 这比你代跑更有用。
3. **定风格标签** —— 必须全英文;过一遍词表校验(见 `references/style-tags.md`)。
4. **写歌词** —— 段落标记英文、非空、时长对齐(见 `references/vocal-styles.md`)。
5. **生成** —— 通过服务提交(推荐,有历史/进度/简谱)或直接 CLI。
6. **氛围后期**(可选)—— ffmpeg 链;两遍处理;参数见 `references/mixing.md`。
7. **交付** —— 列清楚哪些是客观测量、哪些**必须用户听**。

每一步先出一版给用户确认,不要一口气全做完再交付。

## 时长怎么定

**实测精确换算:1 秒 = 25 语义 token**(7 组实测全部命中)。

| 目标时长 | semantic_max_tokens | semantic_min_tokens |
|---|---|---|
| 20 秒 | 500 | 450 |
| 60 秒 | 1500 | 1200 |
| 6 分钟(默认上限) | 9000 | 200 |

- 实际时长**由歌词长度决定**,这两个值只是上下限。
- 通用参数 `--duration-seconds` 对 YuE2 **无效**(静默忽略),别用。

## 生成方式

**推荐走服务**(有任务队列、阶段进度、历史、简谱导出):

```powershell
# GUI 里点,或直接 POST(见 references/commands.md)
```

**也可以直接调引擎**:

```powershell
& D:\mt-tool\yue2-V100\build\bin\Release\audiocpp_cli.exe `
  --task gen --family yue2 `
  --model D:\mt-tool\yue2-V100\models\Yue2-3B-GGUF `
  --backend cuda --threads 8 `
  --request-option style="Mandarin, city pop, warm female vocal, nostalgic" `
  --lyrics "[Verse]`n夜色落在窗台上`n[Chorus]`n如果风还记得那年夏天" `
  --request-option cot=off --seed 831001 `
  --out output\demo.wav --log --metrics
```

- `cot=off` 不写谱、最快;`melody`/`full` 才产 ABC 乐谱并可导出简谱。
- 每首会 spawn 一个新进程 → **多 5–6 秒模型加载**,换来无状态与真实阶段进度。
- **同 seed + 同参数 = 逐字节相同**(已验),想做 A/B 必须换 seed 或换参数。

## 交付时要说什么

- ✅ 客观测量:时长、RTF、分析出的 BPM/宽度/频段占比、后期作用量(锁相相关等)
- ⚠️ **必须你听**:氛围对不对、够不够虚、像不像人声、留哪一版
- ❌ 不要说:"这条听起来…""人声很朦胧"——你听不到
